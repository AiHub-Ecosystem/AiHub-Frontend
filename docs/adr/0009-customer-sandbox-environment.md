# Make the Sandbox Environment a customer Environment

- Status: Accepted
- Date: 2026-09-27
- Issue: [#27](https://github.com/AiHub-Ecosystem/AiHub-Frontend/issues/27)
- Amended by: [ADR-0017](0017-sandbox-backed-scoring-demo.md) for the public demos' Writing/Speaking key scopes and request flow. The signed-in Console continues to create Production-only keys under ADR-0011.
- Related: [aihub-be ADR-0056](https://github.com/AiHub-Ecosystem/aihub-be/blob/main/docs/adr/0056-customer-sandbox-test-tier.md), [aihub-be #182](https://github.com/AiHub-Ecosystem/aihub-be/issues/182), aihub-be ADR-0017, [Sample request and Writing Scoring catalog](../superpowers/specs/2026-09-27-sample-request-design.md), ADR-0003

An **Environment** is the request tier AIHUB derives from the hostname a request is sent to, and an API key works only in the Environments it allows. Until aihub-be #182, the Sandbox Environment belonged to AIHUB alone: the dedicated demo Organization was its only tenant, and a customer key could not allow `sandbox`. That backend change made the Sandbox Environment a customer Environment, and this ADR records what the Customer Web does about it. It refines the Sample request design, which assumed the old boundary; it does not replace any existing ADR.

A Sandbox key is deliberately narrow. When this ADR was accepted, aihub-be accepted it only when `allowed_environments` was exactly `["sandbox"]` and `scopes` was exactly `["writing.grade"]`; ADR-0017 later amends that policy for public demos to allow `writing.grade`, `speaking.grade`, or both while keeping the Sandbox-only environment restriction. The signed-in Console still creates Production-only keys under ADR-0011. The public demo's optional key is held only for the visit, checked separately for the selected skill, and reauthenticated on every grading call.

The Sample request resolves its host from the key's Environment rather than from a fixed literal. The Customer Web keeps that mapping as a constant table, one entry per Environment with a public host, and an Environment absent from the table has no runnable command — a staging-only key shows the request path and an explanation rather than a host it cannot call. Where a key allows more than one Environment that has a public host, the Sample request prefers Sandbox, so a first call still costs the Organization nothing; preferring production would spend a paid request on a sample the holder has not yet chosen to make. The alternative — publishing hosts at runtime from the BFF — was rejected: it adds a configuration route, a runtime-config surface, and their own tests, while the only gain is not redeploying the Console if a hostname changes. That cost is accepted knowingly. The Customer Web and the backend will disagree until the Console is redeployed, and a change to a sandbox hostname is an operational decision that reaches the Console on its own release cycle.

Two things in the Console are therefore static copy rather than read from the system. The Sandbox allowance — 25 dispatches per Organization per UTC month, and 500 across the Sandbox Environment — is **not** exposed by any backend endpoint, response body, or header; the only customer-visible signal is a `429 QUOTA_EXCEEDED` whose `retry_after_ms` is the time to the next UTC month. The Console states the per-Organization figure in one constant that cites this ADR and aihub-be ADR-0056. If the backend changes the figure, the Console is wrong and no test will catch it. That is a known, accepted drift in exchange for telling an owner how many free attempts they actually have, and closing it would require the backend to expose the allowance. Separately, `lib/speaking-gateway.ts` holds a `sandbox.aihubproduction.com` constant for AIHUB's internal Speaking demo gateway. It is the same hostname serving a different purpose, and the two must not be reused for one another.

Graded 2026-09-27. This ADR covers Environment selection, host resolution, and the Sandbox usage copy. It does not add a Task 1 Sample request, change the Console's Production-only key creation, add a public staging host, or change how the raw key is revealed, which remains the one-way path ADR-0003 allows. Public demo key admission and Writing/Speaking scopes are covered by ADR-0017.
